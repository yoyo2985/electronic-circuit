# PCM-over-UART 调试预案（未来有板子时，无 SD 卡情况下检查 mic 前端）

目的：ES8388 数字链路已通，但 mic 模拟前端可能有故障。无 SD 卡时唯一回传通道是 UART(CH340 COM)，
把 FPGA 采集到的 PCM 回传到 PC 分析。

## 1. 带宽估算（重点）
- UART 115200 bps，8N1：有效 ≈ **11520 B/s**（115200/10）。
- 48kHz 24bit 立体声 = 48k×(24/8)×2 = **288 KB/s** —— 远超，不能直传。
- 需 **降采样 + 截位/隔帧**：
  - 目标 8kHz 单声道 16bit = **16 KB/s** → 仍 >11.5 KB/s，还要再压缩；
  - 8kHz 单声道 **8bit**（取高 8 位）≈ 8 KB/s → 可行；
  - 或 8kHz 单声道 16bit 但 **隔帧/只传活动段**（配合能量/VAD），也可在 11.5 KB/s 内。
- 结论（建议）：**传 L 声道 → 降采样 8kHz → 16bit → 每包 16 样本(32B)**，净数据 32B，
  加包头+序号+校验 ≈ 36B/包 → 8k/16=500 包/s × 36 = 18 KB/s 仍超；需 8bit 或降采样 4kHz，
  或 16bit 但 **每 2 帧传 1 帧（有效 4kHz 分析带）** ≈ 9 KB/s 可行。
- 更简单第一版：**只传 RMS/能量 + 少量原始段**（沿用已有 `Pxxxx Lxxxx Rxxxx` 心跳做电平观察）。

## 2. 帧格式建议（16bit，包式）
```
[AA][LEN][SEQ][CHK0]  [PCM16 x N(≤16, 大端)]  [SUM]      （面向解析）
AA=帧头  LEN=数据长度  SEQ=8bit 序号  SUM=Σ 数据低8位校验
```
简化示例（接收端建议）：
```
AA  n  seq  d0h d0l d1h d1l ... d(n-1)h d(n-1)l  cs
```
cs = (AA+n+seq+Σd) & 0xFF。若样本为 8bit，则两样本一字节。

## 3. FPGA 侧（伪代码/设计思路，不写 .v）
- 从 `audio_pcm_bridge` 取 L 声道 24bit；
- 降采样：每 M 个 48k 采样取 1（M=6 →8k；取最近一个）做一阶抗混叠再抽取（可简单平均）；
- 取高 16bit；攒满 16 样本后经 `uart_tx`(115200) 发包（沿用 busy 握手）；串口带宽不足时用“传 1 停 1”节流。
- 仅在需要时开（调试开关），不影响正常采集。

## 4. PC 侧接收
见 `tools/pcm_uart_receiver.py`：打开串口→解析上面帧→存 .wav(8k) 或画波形。
先跑已有 `tools/audio_monitor.py` 看 `Pxxxx` 是否在流（数字链路健康），再跑本接收器看波形是否随说话变化，
从而定位是“ADC 无数据”还是“mic 无声”。

## 5. 验收判据
- 说话时 8k 波形幅度随语音起伏 → mic 模拟前端 OK；
- 恒为接近 0 的噪声 → 前端仍异常（回到 E13 1kHz 注入 / 查模块原理图）。
